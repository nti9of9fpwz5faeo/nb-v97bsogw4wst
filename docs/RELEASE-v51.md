# v51 — STEPS結果画面とダイヤ試遊版

## 今回の変更

- リザルトの主役をSTEPSに。数字のカウントアップ、新記録の演出、前の自己ベストとの差、次の50 STEPS区切りへの目標を表示。
- 判定精度と最大コンボはすぐ確認できる2つのカードに。PERFECT/GREAT/GOOD/MISSの全内訳は展開式で保持。
- 途中で演出をスキップしても、再挑戦しても、獲得報酬は再付与しない。
- エンドレスの各周回に1つ、任意のダイヤマスを追加。そのマスの上でGREAT以上を4回取ると3ダイヤ。空振り、GOOD/MISS、必殺技で通過しただけでは獲得しない。青ノーツの別々の拍の判定はそれぞれ1回。
- ミッションは5系統×4段階。GREAT以上の累計、エンドレスの最高STEPS、最大コンボ、必殺技の累計、ダイヤマスの累計。各段階は一度だけ自動受取、達成通知は右上。チュートリアルは対象外。
- ダイヤの使い道の試作として、コーステーマ「オーロラリンク」（60）、「サンセットドライブ」（160）を解放できる。解放前に確認の2タップ。背景・床・飾りだけが変わり、譜面や強さは変わらない。
- 既存の曲・キャラはそのまま使用可能。旧自己ベスト・設定の保存キーも維持。
- 通常、距離チャレンジ、チュートリアルの結果表示も維持。基本操作、判定幅、曲の拍、倍率、ライフ、必殺技性能には変更なし。

## 保存と報酬

新しい保存キー: `neon-blade-progress-v1`。

`progression.js` は画面と分離した端末内の進行モデル。ミッション報酬は達成時に確定して保存する。一般の進捗は最大1秒で保存し、非表示化・終了・ポーズでも保存する。描画とリザルト再表示は残高を変更しない。

保存失敗は画面に表示。保存できない状態でのテーマ購入は残高と解放をロールバックする。壊れた進行データは自動で上書きしない。音声判定フレームでDOM全体を再構築しない。

このダイヤは**試遊用のローカル通貨**。実課金、広告SDK、サーバー購入検証、アカウント同期は未実装。クライアント内データを本番の課金残高として信頼してはいけない。同時に複数タブでプレイした際の進行マージは未対応。

## 検証

- `node --test tests/progression.test.cjs`：報酬の重複、再読込、最大値型ミッション、解放の二重支払い、残高不足、保存失敗時のロールバック、壊れたデータと既存キーの保護。
- `node tests/browser.test.cjs`：Playwrightが必要。標準Chromium以外は `CHROMIUM_PATH` で実行ファイルを指定。
- 実際の `doAction()` にノーツを渡し、4回の有効な判定→ダイヤマス達成、同じ拍の再処理無効、マス外とGOODの対象外を検証。
- リザルト再描画・スキップ・即リトライで報酬が重複しないこと、旧自己ベストが低い記録で上書きされないこと、テーマの確認操作・購入・再読込、練習の除外を検証。
- Chromium 390×844 / 320×568 で画面確認。320px幅で横にはみ出さず、短い画面でも再挑戦ボタンが見える。動きを減らす設定では演出待ちを省略。
- 実機Androidのタッチ感・音ズレ・獲得頻度の体感は未確認。自動テストの状態は試験ブラウザ内のみで、実ユーザーの保存データには書いていない。

## 次に進める内容（ユーザーとの確認事項を保持）

- Google Play公開予定。プレイ回数は無制限。主役の記録はSTEPS。
- 無料ダイヤはミッションと、たまに出るダイヤマスから。単に毎回プレイしただけの基本報酬は追加しない。
- キャラ/曲をダイヤで解放したい。通常は手頃、凝ったステージは高価。今回のテーマ価格を本番の経済バランスとして確定しない。
- キャラのビジュアル・技・発動条件を磨く。現状のキャラ性能は共通のまま。
- リアルマネーでのダイヤ販売と広告削除を予定。Android化、Google Play Billing、サーバー側の購入検証と保存方式を設計する。
- 採用曲は歌なし。SUNO v6の品質を優先。試作のRunway生成曲は不採用で、この変更には追加していない。
- コースのマンネリ対策は、今回の景色変更に加えて曲の展開と地形/配置の変化を検討する。
- ユーザーの翌日の試遊を受け、リザルトのテンポとダイヤマスで足を止める気持ちよさを調整する。
