# チュートリアル v45

## 対象とねらい

初心者が「キャラに触れた時」「剣先に触れた時」を判定と取り違えないよう、チュートリアルだけで新しい判定位置を試す。
本編の曲・判定位置・判定幅・移動ルールは変更しない。本編への展開は試遊結果を見て別途判断する。

## 練習の流れ

1. お手本：自動で2回斬る。操作は無効。判定統計にお手本は含めない。
2. ブレイク：拍のガイド音のみ。PERFECTまたはGREATを4回。失敗しても成功数は保持する。
3. 曲とブレイク：同じ拍に曲を重ねる。PERFECTまたはGREATを4回。
4. 移動：ブロックのないコースで3回進む。拍の判定はしない。
5. ブレイクと移動：斬ったら移動ボタンが使える。3セット。
6. 青ブロック：1拍目で青から赤へ。次の拍でもう一度斬る。2個。

各段階の成功後は2拍置いて自動で次へ進む。「この練習をやり直す」でその段階を再開できる。
ライフは減らず、曲が終わっても進捗を保持して練習を続ける。通常のゲームオーバー・スコア画面には入らず専用の完了画面を表示する。

## 判定と描画

- 判定枠は `player.idx + 1`。キャラのマスではない。
- 白い◆をブロック中心に描き、黄色い四隅と上下の三角を判定枠に描く。
- ブロックは3拍かけて3マスを等速で移動。`targetBeat` の `beatTime()` で枠中心に到着する。
- 通常の判定幅を使用：PERFECT ±45ms、GREAT ±90ms、受付 ±170ms（100 BPM）。
- 早い有効入力は押下時刻で採点し、到着する拍に斬る。遅い有効入力はすぐ斬る。
- 入力イベントの処理遅延があっても、発生時刻が受付内なら直前の練習MISSを戻す。
- 保存済みのノーツ速度は練習では使わず、設定値そのものは変更しない。端末の手動タイミング補正・音量設定は尊重する。
- 練習では背景の拍フラッシュと画面揺れを止め、視線を判定枠に集める。

## 音

`audio/tutorial.mp3` 自体は変更していない。全144秒の音源を解析した結果、周期はほぼ100 BPMで一定だった。
設定の `offset` を0.070秒から0.005秒へ変更。スペクトルの立ち上がりと短時間の高域エネルギーの立ち上がりを照合し、旧設定が約60〜70ms遅いことを確認した上での補正。
これは音源上の解析であり、実機の出力・タッチ遅延を保証するものではない。

初めの2段階では曲をミュートし、専用ガイド音を100 BPMで予約再生する。3段階目から曲の音量を0.7へフェードインする。
ガイド音・曲・描画・入力判定は既存の共通時計と `beatTime()` を使う。ユーザーのガイド音設定は書き換えず、練習中だけガイド音を有効にする。

## 確認したこと

- Chromiumで実時間のお手本2回が自動で次へ進み、お手本がユーザーの判定回数に入らないこと。
- タッチ入力の経路で練習が進み、早押し・遅れ・二重タップ・青の2拍目失敗で詰まらないこと。
- 入力処理遅延の取り消し、音源ループ後の進捗保持、一時停止・再開・やり直し・完了。
- スマホ幅と小さい画面で説明・フィードバック・ボタンが画面内に収まること。
- 本編へ戻ると練習UIと音の設定が解除され、本編のブレイクは従来の自分のマスだけを対象にすること。

実機で次に確認したい点：初見の人が枠の中心を見て押せるか、音だけでも同じ拍を取れるか。端末固有の遅延は診断モードで別途測る。
